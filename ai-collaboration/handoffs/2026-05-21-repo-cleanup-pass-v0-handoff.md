# Handoff: Repo Cleanup Pass v0

Date: 2026-05-21

Project: anyu-next / 暗語 ANYU

## Objective

Run a conservative first repo cleanup pass based on the completed Repo Architecture + MVP Leftover Audit v0.

This task should address the highest-confidence cleanup and organization items without risking active production code or useful research/tooling history.

Primary goals:

```text
- reduce privacy risk from committed raw/sample outputs
- create clearer archive/index boundaries
- document and classify MVP/prototype leftovers
- inspect oradar/ internally without deleting it wholesale
- preserve reusable jsonl → topic/question tooling candidates
- avoid damaging active production runtime
```

This is a conservative cleanup + documentation task.

Do not broadly delete active code.

Do not move `oradar/` wholesale.

Do not change app behavior, runtime, model, prompt/schema, DB schema, legal semantics, LINE flow, auth, payment, portal, production ops behavior, or product logic.

## Background

Repo Architecture + MVP Leftover Audit v0 completed.

Key audit findings:

```text
- Active production-critical path is concentrated in apps/web/.
- Canonical design/legal/ops docs are under docs/.
- ai-collaboration/ contains historical evidence and workflow artifacts.
- Main current repo risk is documentation/history sprawl and committed raw sample text, not active app instability.
- No committed live secrets were found.
- Main privacy-review item: committed raw sample text under outputs/raw/, outputs/product_eval/raw/, and outputs/product_samples/raw/.
- Legacy/prototype areas like experiments/ambiguous_temperature_v0/, oradar/, and scripts/ were classified conservatively.
```

User clarification about `oradar/`:

```text
oradar was originally intended to run Dcard fetching/scraping, but Cloudflare blocked that path.
The user later obtained hot article lists using other tools.
The Dcard crawler/fetching path is unlikely to be reused.
However, reusable structured jsonl → topic/question tooling remains valuable.
```

Therefore:

```text
Do not delete oradar/ wholesale.
Classify its internal files.
Archive/delete Dcard crawler candidates later.
Preserve/extract jsonl transformation / topic-question generation candidates later.
```

Recommended later follow-up:

```text
Oradar Topic Tool Extraction Plan v0
Extract Topic Ingestion Tools v0
```

## Scope

Do:

1. Review the audit report.
2. Handle committed raw/sample output risk conservatively.
3. Add or update `.gitignore` patterns to prevent future raw outputs/test artifacts from being committed.
4. Add repo/doc index notes if missing and low-risk.
5. Create archive-boundary documentation if useful.
6. Internally inventory `oradar/`.
7. Classify `oradar/` internals into crawler/archive vs reusable transformation/tooling candidates.
8. Document `experiments/`, `scripts/`, and other MVP leftover boundaries.
9. Update cleanup report, execution report, summary log.
10. Commit and push to `origin/staging`.

Do not:

- delete active production files
- delete `oradar/` wholesale
- move `oradar/` wholesale
- move reusable tools in this pass
- delete historical handoffs/reports
- delete design/legal/ops canonical docs
- rewrite docs massively
- refactor active app code
- change runtime/model/DB/LINE/legal behavior
- run production actions

## Cleanup Priority

### P0: Privacy / raw outputs

Inspect:

```text
outputs/raw/
outputs/product_eval/raw/
outputs/product_samples/raw/
```

Decide conservative action:

- If contents are clearly raw/private-like samples and not needed for active tests:
  - prefer removal from active repo or move to archive only if safe.
- If contents are useful fixtures:
  - redact / replace with synthetic fixtures.
- If uncertain:
  - do not delete; mark NEEDS_HUMAN_REVIEW.

Do not paste raw text into reports.

If removing files:

```text
- ensure no active code/tests import them
- document counts and paths, not contents
- add ignore patterns for future raw output folders
```

### P1: oradar internal inventory

Do not delete `oradar/` wholesale.

```text

jsonl parser / structured transform → keep/extract candidate
topic/question generation → keep/extract candidate
tests/fixtures → follow relevant code
```

Produce a table:

```markdown

|---|---|---|---|
```

Classification options:


Do not move files yet unless the audit shows a high-confidence empty/deprecated artifact and no references.
