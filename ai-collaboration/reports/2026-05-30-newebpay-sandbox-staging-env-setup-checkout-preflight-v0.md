## 1. Source and Route Preflight

Checkout route:

- `POST /api/modules/[moduleSlug]/checkout/newebpay`
- For Module 01: `POST /api/modules/ambiguous-temperature/checkout/newebpay`

Runtime gates/auth:

- Requires `ENABLE_NEWEBPAY_CHECKOUT=true`.
- If `ENABLE_PAYMENT_RUNTIME=false`, requires operator header `x-operator-test-secret` with `OPERATOR_TEST_SECRET`.
- If checkout gate is disabled, route returns JSON `404 not_found`.
- If payment runtime is disabled and operator auth is missing/invalid, route returns JSON `401 unauthorized` after checkout gate is enabled.

Required provider/env names from implementation:

| Purpose | Implemented Env Name | Notes |
|---|---|---|
| Merchant id | `NEWEBPAY_MERCHANT_ID` | Required. |
| Hash key | `NEWEBPAY_HASH_KEY` | Required; implementation requires length 32. |
| Hash IV | `NEWEBPAY_HASH_IV` | Required; implementation requires length 16. |
| Gateway URL | `NEWEBPAY_CHECKOUT_URL` | Required. The code does not read `NEWEBPAY_GATEWAY_URL`. |
| Site base URL / ReturnURL base | `NEXT_PUBLIC_APP_URL` | Required. ReturnURL is constructed from this base. |
| NotifyURL | `NEWEBPAY_NOTIFY_URL` | Required. |
| Provider environment label | `NEWEBPAY_ENVIRONMENT` | Optional label: `production`, `staging`, `sandbox`, otherwise `unknown`. The code does not read `NEWEBPAY_ENV`. |
| Checkout session signing | `PAYMENT_CHECKOUT_SESSION_SECRET` | Required for `pcs_` handoff. |

Version handling:

- Implementation hard-codes `NEWEBPAY_MPG_VERSION = "2.0"` in `apps/web/src/lib/payments/newebpay/checkout-payload.ts`.
- No backend `NEWEBPAY_VERSION` env var is required by current code.
- Owner not finding an MPG version field in NewebPay backend is not a blocker for current ANYU code.

Amount/price:

- Implementation uses `MODULE_01_PRICE_MINOR = 49`.
- Currency is `TWD`.
- Checkout payload `Amt` should be `49`, matching the current public NT$49 price.

Order number format:

- Merchant order number is generated as `ANYUNP` + 24 uppercase hex chars.
- Total length is 30 chars.
- It is deterministic by `moduleSlug` and idempotency key/result id.

NotifyURL / ReturnURL construction:

- NotifyURL is read from `NEWEBPAY_NOTIFY_URL`.
- ReturnURL is constructed as:
  - `${NEXT_PUBLIC_APP_URL}/m/{moduleSlug}/payment/return?merchantOrderNo=...&checkoutToken=pcs_...`
- ReturnURL includes session-bound `pcs_` checkout token.
- ReturnURL remains non-mutating.

ClientBackURL:

- Current implementation does not include `ClientBackURL` in the NewebPay TradeInfo payload.
- If NewebPay review/sandbox requires ClientBackURL, that should be a follow-up code task.

Payment method fields:

- Current implementation does not set provider payment method restriction fields.
- First sandbox E2E should use credit-card one-time payment by selecting that method in the NewebPay sandbox payment page.
- If the provider must hide/force non-credit-card methods, add a follow-up code task to include the correct NewebPay fields after confirming provider docs.

Checkout payload fields currently built inside encrypted TradeInfo:

- `MerchantID`
- `RespondType=JSON`
- `TimeStamp`
- `Version=2.0`
- `MerchantOrderNo`
- `Amt`
- `ItemDesc`
- `ReturnURL`
- `NotifyURL`

Public checkout response includes encrypted `TradeInfo` and `TradeSha`; these should not be pasted into reports because they are usable provider payment payload fields.
