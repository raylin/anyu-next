## High-Level Finding

The current owner-fill list is too broad. Several keys currently blank in mirrors are not owner secrets:

- runtime flags can be set by Codex from policy
- model names/strategy can be set by Codex from policy
- provider endpoint URLs can be set by Codex from policy
- queue provider/topic can be set by Codex from policy
- internal auth secrets can be generated by Codex

The owner should not be asked to fill these blindly.

The owner truly needs to provide or preserve provider-issued credentials and DB URLs. Stateful app-owned crypto can be regenerated only with an explicit reset/migration decision.

## Recommended Env Mirror Strategy v2

Recommendation: Hybrid.

Rationale:

- Preserve provider-issued credentials and DB URLs.
- Codex should fill plain config and runtime flags from documented environment policy.
- Codex should generate internal auth tokens local mirror first, then sync Vercel.
- Because no real users rely on current test data, reset access-link/contact/paid-token test data and regenerate app-owned stateful crypto rather than trying to recover old Vercel-only values.

### Option A: Minimal owner-fill

Pros:

- Least operational change.
- Preserves all existing test rows and links.

Cons:

- Keeps old Vercel-only stateful secrets alive.
- Requires owner to recover values that should not be owner-managed.
- Continues ambiguity around app-owned crypto provenance.

Use only if preserving old staging/production test artifacts matters.

### Option B: Clean reset

Pros:

- Cleanest future migration story.
- Codex can regenerate all app-owned crypto local mirror first.
- Eliminates Vercel-only app-owned secrets.

Cons:

- Requires deliberate data clearing.
- Invalidates all old access links, checkout sessions, and test paid access artifacts.
- Needs careful production freeze verification afterward.

Useful if owner wants maximum cleanliness before production smoke.

### Option C: Hybrid

Pros:

- Preserves provider credentials and DB branches.
- Resets only app-owned stateful/token/contact artifacts.
- Lets Codex own internal/plain config while owner owns provider credentials.
- Minimizes owner-fill list.

Cons:

- Requires a precise reset script/plan and validation.
- Old test links/results may be invalidated depending selected tables.

Recommended.
